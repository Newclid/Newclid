Backend API reference
=====================

This page explains how the hand-written backend developer guide relates to
generated API documentation.

The backend has two kinds of reference material:

- FastAPI/OpenAPI documentation generated at runtime by the backend service.
- Sphinx API documentation generated from Python source files, when the backend
  package is included in ``docs/reformat.py``.

Backend OpenAPI reference
-------------------------

When the FastAPI server is running locally, open:

.. code-block:: text

   http://127.0.0.1:8000/docs

This page is generated by FastAPI and shows the current request and response
schemas for endpoints such as ``POST /api/jobs`` and
``GET /api/jobs/{job_id}/result``.

Backend Sphinx API reference
----------------------------

The hand-written developer guide should stay conceptual and task-oriented. It
should not duplicate every class, field, and function docstring.

If the backend package is included in Sphinx API generation, the generated
backend module pages should live under:

.. code-block:: text

   docs/source/newclid_backend.rst
   docs/source/newclid_backend.*.rst

Those generated files belong to ``source/`` and should be regenerated, not
hand-edited.

Backend API reference rule
--------------------------

Use this split:

.. list-table::
   :widths: 36 64
   :header-rows: 1

   * - Documentation type
     - Put there
   * - Hand-written backend docs
     - Architecture, module responsibilities, extension guides, operational behavior, and design decisions.
   * - Generated Sphinx API docs
     - Function signatures, Pydantic model fields, and module-level API reference.
   * - FastAPI OpenAPI page
     - Exact live HTTP request and response schemas for a running backend instance.
